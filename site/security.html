TRUST & SECURITY / 04

Evidence before trust.

Know what a check means, what it misses, and who published the code.

Omarchy plugins run unsandboxed with your user permissions. Automated checks do not establish that code is safe.

Two clearly different states

○ Unverified listing Metadata read from a public repository. Its maintainer has not published a checked release here.

✓ Checks passed Repository ownership or write-access proof, manifest schema, declared entry-point files, size limits, absence of symlinks and submodules, repository identity, and version immutability passed at the listed commit.

What we do not claim

We do not execute submitted code, perform a complete security audit, or guarantee compatibility with your installed shell. Limited entry-point pattern hints are not a malware scanner. Dependencies, scripts, dynamically downloaded code, and QML imports need separate review.

Inspect the supply chain

  • Review the exact commit and compare it with the last version you used.
  • Check upstream security advisories and the repository’s dependency graph.
  • Look at maintainer history, repository age, and unexpected ownership or code changes.
  • Use ecosystem-specific dependency auditing where it applies. A passing npm audit does not audit QML or shell scripts.

Repository stars and age are context, not safety scores. We do not measure downloads or installations. Copying a command is not a download.

Versions and publisher history

Accepted version numbers cannot be reassigned to a different SHA. Each receipt records the publisher, source commit, repository ID, manifest digest, warnings, and publication time. GitHub issue comments are the public ledger, not a cryptographically immutable transparency log: privileged administrators can remove comments, so retain receipts for your own records.

Installation

The usual Omarchy marketplace install command follows upstream code and may not install the commit shown here. This site links directly to the recorded source snapshot. Review upstream instructions and source before installing. Do not treat an unpinned install as verified.

Report a concern

Report privately on GitHub ↗. Registry administrators can suspend a repository through a reviewed blocklist change. Suspensions remove it from the catalogue on deployment; they cannot remove software already installed on your computer.
