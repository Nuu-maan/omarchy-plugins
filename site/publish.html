Already listed? Same process.

Increase the version in your manifest and submit its new commit. Existing versions keep their original SHA. Repeating the same version and SHA is a no-op. The highest accepted version stays the default.

Publishing for a team or organization

Open a submission first to obtain an issue number. Commit .omarchy-registry.json at the repository root with the values below, update the submission to that commit, and reopen it. The proof must name the person who opened the issue.

{
  "registry": "Nuu-maan/omarchy-plugins",
  "publisher": "your-github-login",
  "issue": "https://github.com/Nuu-maan/omarchy-plugins/issues/123"
}

What happens next

The workflow checks ownership, manifest structure, declared files, repository identity, and version integrity without running plugin code. A passing request receives a public receipt. The next successful catalogue deployment makes it visible. GitHub runner availability and API limits can delay processing; there is no fixed-time guarantee.
